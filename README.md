# 跑步机跑姿分析 Web Demo

本项目按 `方案.md` 实现视频/摄像头 → MediaPipe Pose → 步态事件 → 指标与报告的流程，适合固定机位拍摄的单人侧面跑步画面。它是可在浏览器中使用和部署的演示项目，分析结果仅供运动观察。

## 本地启动

推荐 Python 3.10 或 3.11，并使用独立虚拟环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

程序会自动打开 `http://127.0.0.1:8000`。如果是在无桌面的服务器上启动，使用 `python app.py --no-browser`，再自行打开该地址。

界面提供三种模式：

- **视频分析**：上传 MP4、MOV 或 AVI 后，在原视频上逐帧叠加 MediaPipe 骨架。播放或拖动进度条时，膝/髋关节曲线、游标和当前数值同步更新。单次上传上限为 2 GB。
- **实时摄像头**：经浏览器授权后，在摄像头画面上实时绘制骨架，并连续绘制左右膝关节角度曲线。
- **分析历史**：查看已完成的指标和报告；原视频仍存在时，可以创建一次新的重新分析，不覆盖旧结果。

### 足部周期与稳定性

每侧以**相邻两次同侧着地**作为一个周期。足尖位置相对可见髋部的中点计算，再除以同一身体尺度；左右图使用相同的坐标范围，纵轴向上为正。每个可绘制周期按时间/周期相位插值为 64 个点，所有可绘制周期求得各自侧别的平均曲线。逐周期数值是该轨迹与**本侧平均曲线**的二维均方根距离；总体偏差汇总所有可比较周期的偏差，另列左右平均轨迹之间的距离。数值越小，表示这段视频里的轨迹重复性越高。

结果页会画出所有可绘制周期和平均曲线。鼠标悬停周期条目可突出对应曲线，点击条目可跳到视频中的对应位置。少于 3 帧有效关键点的周期仍会列出，但标为“无法绘制”；有效帧比例低于 60% 的可绘制周期标为“低置信度”。同侧不足 2 个可绘制周期时无法计算该侧偏差。点击“查看完整分析简报”可展开结论，也可下载 `report.html`。

稳定性分级只是 Demo 中的经验提示，受拍摄角度、遮挡和着地事件检测影响；不能据此判断跑姿优劣或伤病风险。新分析会保存逐帧实际时间戳，用于可变帧率视频的骨架、曲线与播放进度同步。

### 分析历史与数据

浏览器界面产生的上传视频与结果默认保存在 `output/jobs/<任务 ID>/`，包括原视频 `source.<扩展名>` 和下述分析文件。设置 `PACE_DATA_DIR` 可更改 `output` 的位置。历史页可以查看已有结果；原视频仍在时可重新分析，新结果单独保存，不覆盖旧任务。服务启动时会将含有逐帧关键点的旧 `timeline.json` 自动升级为当前足部周期结果；缺少这类数据的旧任务需要重新分析原视频。

所有视频和摄像头画面都由当前服务处理。部署到远程服务器时，浏览器会把画面发送到该服务器。

## 命令行用法

```bash
python main.py input/test.mp4 --output output
```

输出包括：

- `annotated.mp4`：骨架、膝角、步频和步态事件叠加视频
- `landmarks.csv`：33 个关键点的原始值与平滑值
- `metrics.json`：步频、步时、关节 ROM、左右差异、规则反馈和足部稳定性摘要
- `report.png`：指标 Dashboard、膝角曲线和足部轨迹
- `report.html`：可展开的简要文字报告
- `timeline.json`：逐帧骨架、角度、事件、时间戳，以及全部足部周期轨迹和偏差

## 部署到服务器

服务器安装 Docker 和 Compose 后，在项目目录运行：

```bash
docker compose up -d --build
```

默认只监听服务器的 `127.0.0.1:8000`，分析历史和上传视频保存在 `pace_data` Docker 卷中，容器重建后仍可读取。服务提供 `/healthz` 健康检查接口。查看运行状态：

```bash
docker compose ps
docker compose logs -f pace-lab
```

远程访问时，建议由现有反向代理将 HTTPS 域名转发到 `127.0.0.1:8000`，并在代理层设置登录保护和与应用 2 GB 上限匹配的请求体限制。浏览器摄像头在远程访问时需要 HTTPS；直接打开服务器的 HTTP 地址通常无法授权摄像头。此 Demo 的任务状态保存在单个 Web 进程内，因此部署配置固定为 1 个 Gunicorn worker；不要横向启动多个副本共用同一份历史目录。

不用 Docker 时也可以设置持久化目录并以单进程启动：

```bash
export PACE_DATA_DIR=/srv/pace-data
gunicorn --bind 127.0.0.1:8000 --workers 1 --threads 4 --timeout 300 app:app
```

## 拍摄建议

- 固定机位、完整侧面、全身入镜；尽量避免遮挡。
- 建议 720p 以上、约 30 FPS，至少包含多个完整步态周期。
- 二维单目视频无法提供实验室级三维运动学结果；输出仅供运动观察。
